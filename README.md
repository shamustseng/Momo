# MOMO 渠道工具

兩個獨立的單一 HTML 檔案，無需安裝任何套件，直接以瀏覽器開啟即可使用：

- `index.html` — **MOMO 渠道談判測算器**（抽成調整與行銷效益追蹤）
- `order-check.html` — **訂單出貨核對**（每日核單與月報表）
- `lark-sync/` — 選用：把 Lark 共用資料夾的檔案抓到本機，供上面的核對工具使用（Windows）

# MOMO 渠道談判測算器（`index.html`）

## 背景

依據《MOMO 渠道合作深化與行銷提案報告》（2026/08/11）：向 MOMO 爭取將平台抽成自
26.5% 調降至 10.0%，差額 16.5% 以 1:1 比例回投聯合行銷，並假設下半年度業績每月成長
1.5 倍。本工具將報告中的測算模型重建為可互動調整的計算機，並補上原報告沒有的部分：

- **談判論點**：計算「損益兩平成長率」——業績成長需達到多少，MOMO 在新方案下收到的
  抽成金額才不會低於「維持現狀、業績不變」的情境，並生成可直接貼入提案的摘要文字。
- **敏感度分析**：不同月成長率假設下的累計結果，說明目前 1.5 倍假設的安全邊際。
- **實際成效追蹤**：合作啟動後逐月回填實際業績與實際行銷投入，自動計算達成率與邊際
  ROAS，用以驗證「行銷投入 ↔ 業績成長」的關係、作為續談籌碼。
- **毛利與行銷投入平衡點**：以阿爾法餐飲整體毛利率（0%–15% 可調）估算毛利額，對比投入
  MOMO 渠道的行銷預算，算出打平所需毛利率、現行毛利率下可承受的回投比例上限，避免業績
  翻倍的同時實際上是虧本衝量。

## 使用方式

1. 直接用瀏覽器開啟 `index.html`（雙擊，或 `python3 -m http.server` 後於瀏覽器開啟）。
2. 在「假設設定」調整基期業績、抽成、回投比例、成長假設等參數，所有區塊會即時重算。
3. 每月談判/合作有實績後，於「實際追蹤」表格輸入實際銷售額與實際行銷投入。
4. 所有輸入（假設與實際數據）會自動保存在瀏覽器 `localStorage`，重新整理不會遺失。

## 檔案

- `index.html` — 完整工具（HTML + CSS + JavaScript，無外部依賴）。

# 訂單出貨核對（`order-check.html`）

每天丟進兩個資料夾，逐張比對「該出的貨」與「實際出的貨」，月底輸出當月出貨報表。

## 解決什麼問題

打單出貨後，最常見的錯誤是收件資訊被改動、數量出錯、漏出貨、或出了不該出的單。這些
錯誤在客訴進來之前不會有人發現。本工具在出貨當下就把差異挑出來。

## 出貨檢查模式（給倉庫同事，例如 Lance）

打開工具預設就是這個模式（頂端可切到「主管對帳」）。字大、一次只做一件事、話講白，
給不熟電腦或需要多一點引導的同事用：

1. **放入今天的訂單**：先點今天出貨的倉庫（希塔倉／愛上倉／Momo 倉，可在主管模式改），
   再把 momo 後台下載的訂單檔放進來（或按「從 Google Drive 拿今天的訂單」）。
   有密碼的 PDF／Excel 會用主管設定的文件密碼自動打開。畫面直接顯示「今天要出 N 張單」，
   打不開的檔案會列出來請主管看。
2. **一張一張檢查**：每張單一頁，收件人、電話、地址、商品與數量、金額各一行，
   看過沒問題就點一下打勾；全部打勾才能按「這張沒問題，下一張」。有問題的按
   「這張有問題，先放一邊」並選原因（資料不對／貨不夠／找不到商品／其他）。
   進度存在瀏覽器裡，中途關掉再開會接著做。
3. **上傳出貨**：全部檢查完才出現「可以上傳到出貨系統了」與上傳步驟；有問題的單另列
   一張清單交給主管。可以「存成今天的紀錄」（進主管模式的每日紀錄與月報）與匯出檢查清單 CSV。

主管模式裡有「出貨檢查模式的設定」卡：使用者名字、倉庫清單、上傳步驟說明、文件密碼、
預設進入哪個模式。網址加 `#pro` 直接進主管對帳、加 `#guided` 直接進出貨檢查。

### 文件密碼

momo 等平台匝出的檔案常整份鎖密碼。工具會自動試：主管在設定填的文件密碼、Excel 的預設
密碼、空密碼（只鎖擁有者權限的 PDF）。支援的加密：PDF 標準加密（RC4 40/128、AES-128、
AES-256）、Office 2007+ 的 xlsx/docx 密碼（Standard 與 Agile）、Excel 97-2003 的 .xls
（RC4 CryptoAPI）。密碼存在這台電腦的瀏覽器裡；**這個 repo 是公開的，程式碌裡不放密碼**，
線上版（claude.ai Artifact）也不內建：主管在 Lance 用的那台電腦、主管對帳 → 設定裡填一次即可。

## 使用方式

1. 用瀏覽器開啟 `order-check.html`（雙擊即可）。
2. **當天全部訂單**：整個資料夾拖進來，或按「選擇資料夾」。
3. **實際出貨明細**：打完出貨單後的資料夾，同樣整包丟進來。
4. 到「逐檔擷取結果」確認每個檔案抓到的資料；抓錯的直接改，不該算的取消勾選。
5. 按「開始核對」，檢視差異；點任一列可展開，逐欄比對訂單與出貨。
6. 按「存為當日紀錄」，資料歸入該日期。
7. 月底到「月報表」選月份，匯出 CSV。

## 支援的檔案格式

一個資料夾裡可以混合下列格式，一個檔案一張單、或一份檔案含整天的單，都讀得到：

| 格式 | 讀取方式 |
| --- | --- |
| `.xlsx` | 直接解析（讀 zip 結構 + 瀏覽器內建解壓縮），表格型與表單型都支援 |
| `.xls`（Excel 97-2003） | 直接讀 OLE 容器與 BIFF8 記錄；**含 RC4 加密的檔**：自動試文件密碼與 Excel 預設密碼 |
| `.csv` / `.tsv` / `.txt` | 自動判斷 UTF-8 / Big5 / UTF-16 編碼與逗號／分號／Tab 分隔 |
| `.docx` | 解析段落與表格 |
| `.pdf` | 抽取內嵌文字（含 CJK 的 ToUnicode 對照表）。**試算表印成的 PDF** 會用文字座標把表格還原：同一列的儲存格、標題對欄位，寬表被切成幾段印也會接回同一筆 |

不支援的會明確標示、不會默默略過：Excel 5.0/95 的 `.xls`、XOR 或舊式 RC4 加密的 `.xls`
（請另存新檔）、圖片檔、以及掃描或拍照產生的 PDF（裡面沒有文字可抽）。上傳區的摘要會直接寫出有幾個檔案讀不到、原因是什麼，
不用自己去逐檔清單裡翻。

讀不到的檔案在逐檔清單裡有「手動填入這張單」按鈕，按下去會出現空白可編輯的一列，
自己把單號、收件人、數量金額打進去就能一起核對——不會因為幾張掃描件就整批卡住。

**PDF 的實際限制**：能不能讀到字，取決於 PDF 裡有沒有文字。系統直接輸出的 PDF（瀏覽器
列印、Word／Excel「另存為 PDF」、Acrobat、報表引擎）讀得到，包括把頁面與字型壓進物件串流
（`/ObjStm`）、字型定義放在父層繼承、串流用 PNG 預測器的寫法；掃描件、拍照轉檔的沒有文字可
抽，讀不到；有密碼的 PDF 會用文件密碼自動打開（見「文件密碼」）。每個檔案抓到什麼都會列在「逐檔擷取結果」讓你確認，
讀不到的會標成「讀不到」並說明原因，可以手動補。

## 逐檔擷取怎麼運作

每個檔案會找出訂單編號、收件人、電話、地址、商品、數量、金額。判斷順序：

1. 檔案本身是**表格**（有標題列、欄位對得上）→ 一列一張單。
2. 一份文件裡**連續多張單**（出貨明細、宅配單）→ 以每張單的「訂單編號」為錨點切段，
   一段一張單。會自動判斷欄位是印在單號後面（明細）還是前面（宅配單）。同一張單在同一
   份文件印兩份（貨件聯／收執聯）只算一次。
3. 否則視為**單一單據**，用標籤找值（標籤與值分行也讀得到），遇到下一個欄位標籤就切斷。
4. 內容裡找不到訂單編號時，退而從**檔名**取（例如 `出貨_A2601.pdf` → `A2601`）。

同一張單出現在**不同檔案**（例如 momo 的明細、宅配單、總表各一份）視為同一筆出貨的多份
文件：收件人取明細的、電話地址取宅配單的，數量與金額**不會重複加總**；被遮罩的值
（`林*鳳`、`****路37號`）會讓位給完整的值。

擷取結果全部可以手動修改，改完直接重新核對。

### 已用真實 momo 檔案驗證

「第三方列印」輸出的三份 PDF（出貨總表、明細、宅配單，經 iLovePDF 解鎖）：明細與宅配單
各讀出全部訂單，合併後每張單有訂單編號、收件人、電話（含 momo 隱碼分機）、地址、品項
數量。出貨總表是印成 PDF 的表格，會以座標還原成 13 欄的表格讀出 5 張單，與明細、宅配單合併成同一筆。
momo 訂單查詢印成的 PDF（寬表被切成 6 段）也能接回 24 欄的表格；不過建議訂單側直接放匯出的
`.xls`，資訊最完整。

momo 後台匯出的訂單 `.xls` 是用 **Excel 預設密碼加密的舊版 Excel**（Excel 開啟時不會問密碼，
所以看起來像沒加密）。工具會自動用同一把預設密碼解開，直接放進訂單資料夾即可，不用轉檔。

## 連 Google Drive（選用）

工具最上方有「從 Google Drive 讀取當天的兩個資料夾」：選日期、按一下，會在 Drive 的
「出貨記錄」底下找到那天的訂單與出貨資料夾，把檔案讀進來解析。認得兩種擺法：

- `出貨記錄／0908 訂單`、`出貨記錄／0908 出貨`
- `出貨記錄／20260908／訂單`、`出貨記錄／20260908／出貨`

資料夾名稱裡的數字等於 `0908`、`20260908` 或 `260908` 都算同一天；含「訂單」的是訂單側、
含「出貨」的是出貨側。Google 試算表／文件會自動匯出成 xlsx／docx 再解析。

有兩種連法，工具會依所在環境自己選：

| 開啟方式 | 連法 | 要設定什麼 |
|---|---|---|
| claude.ai 上的線上版（Artifact） | 用你在 claude.ai 連好的 **Google Drive 連接器** | 不用設定。第一次會問你是否允許這個頁面使用連接器 |
| GitHub Pages 等 https 網址 | 頁面自己向 Google 登入取唯讀權杖 | 一次性建 OAuth 用戶端 ID（見下方） |
| 本機雙擊 `file://` | 不能連 Drive | 手動拖資料夾 |

### 線上版：claude.ai 連接器

在 claude.ai 開這個工具時，讀 Drive 走的是看頁面的人自己在 claude.ai 連好的 Google Drive
連接器，用的是他自己的 Google 授權；頁面拿不到任何密碼或權杖，只呼叫「搜尋檔案」與
「下載檔案內容」兩個唯讀功能。前提：

- 帳號要在 claude.ai 設定 → 連接器（Connectors）加入 Google Drive。
- 第一次按讀取時，claude.ai 會問是否允許這個頁面使用 Google Drive 連接器，選允許。
- 讀得到哪些資料夾，取決於那個 Google 帳號在 Drive 上看得到什麼。

頁面會依錯誤原因提示下一步（授權過期→到連接器重新連接；沒加連接器→去加；公司政策
擋住→改手動拖）。這個模式只給同組織的人用；要給外部人員用，請用 GitHub Pages 版。

### https 網址版：要先建 OAuth 用戶端

Google 登入不能在本機雙擊開的 `file://` 上跑。把 `order-check.html` 放到任何 https
靜態網址即可，最省事的是 GitHub Pages（本 repo 的 Actions 會自動部署）。手動拖資料夾不受此限制。

#### 一次性設定（Google Cloud，約 10 分鐘）

1. 到 Google Cloud Console 建一個專案（或用現有的）。
2. 「API 和服務 → 程式庫」啟用 **Google Drive API**。
3. 「OAuth 同意畫面」：使用者類型選 **內部**（Google Workspace 帳號可選，不用送審）；
   若是一般 Gmail 只能選外部，改為「測試中」並把會用的帳號加進測試使用者。
   範圍加入 `.../auth/drive.readonly`。
4. 「憑證 → 建立憑證 → OAuth 用戶端 ID」，類型 **網頁應用程式**，
   「已授權的 JavaScript 來源」填工具所在的網址來源（例如 `https://你的帳號.github.io`）。
   不需要重新導向 URI。
5. 把產生的用戶端 ID（`xxxx.apps.googleusercontent.com`）貼進工具的「Google OAuth 用戶端
   ID」欄位。它會存在這台電腦的瀏覽器裡。

第一次按「連線」會跳 Google 登入並詢問是否允許唯讀存取 Drive；同意後這次瀏覽期間不再問。
「登出 Google」會清掉授權。工具只讀取，不會寫入或刪除 Drive 上的任何東西。

## 核對內容

以**訂單編號**為對應依據，同一張單有多筆資料會自動合併計算，比對：

| 項目 | 說明 |
| --- | --- |
| 收件人 | 忽略空白與全形半形差異 |
| 電話 | 預設只比後 9 碼，`+886`、`(02)`、`-` 等格式差異不誤判 |
| 地址 | 預設寬鬆比對，忽略空白、全形半形、臺／台、郵遞區號、樓／F |
| 數量 | 整張單加總，或逐項商品比對；可設容差 |
| 金額 | 整張單加總；可設容差（四捨五入誤差可填 1） |

結果分四種狀態：**正確**、**資料不符**（欄位有出入）、**未出貨**（訂單有、出貨沒有）、
**多出貨**（出貨有、訂單沒有）。

### 訂單編號對不起來時

兩邊的單號寫法常常不一致。完全相同配不到時，會再放寬兩輪：

1. 忽略符號差異——`A-2601` 對上 `A2601`。
2. **只要有連續 N 碼相同就算同一張**，N 預設 5、可在「核對規則」調整。
   `SF-A2601-01`、`X99A2602Z` 都能對回 `A2601`、`A2602`。

第 2 輪會挑「最相似」的那一張，不是隨便一張；如果有兩張以上同樣相似，判定為分不出來，
保留為未出貨並在提示裡列出候選，不會亂配。碼數調低誤配風險就升高——5 碼大約是實用下限。

放寬配到的單會標上「相近單號」，訂單編號那格也會標紅，不會安靜地混過去。整個放寬機制可
以在「核對規則」關掉。

如果一張都配不起來，核對結果上方會直接把兩邊實際抓到的單號並排列出來，通常一眼就看得出
是抓錯欄位（例如抓到託運單號）還是只是寫法不同。

## 資料存放

- 解析、比對、報表全部在瀏覽器內完成，**檔案不會上傳到任何地方**，也不需要連網。
- 每日紀錄存在瀏覽器 `localStorage`。換電腦或清瀏覽器資料會消失，請定期用「備份全部
  紀錄（JSON）」匯出。
- 為控制容量，每日紀錄只保存彙總數字與**異常明細**，核對正確的單不逐張留存。

## 輸出

- 差異清單 CSV／完整核對表 CSV（當日）
- 當月報表 CSV：逐日出貨張數、數量、金額、異常張數、正確率，含合計列
- 當月異常明細 CSV
- 全部月份彙總 CSV
- 列印／存 PDF

CSV 皆含 UTF-8 BOM，用 Excel 直接開不會亂碼。

# 從 Lark 抓檔案（`lark-sync/`，選用）

如果同事是把單子丟到 **Lark 雲空間的共用資料夾**，這支腳本每天把兩個資料夾抓到本機，
再把抓下來的 `orders` 與 `ships` 拖進 `order-check.html`。

Windows 內建的 PowerShell 就能跑，**不用安裝任何東西**。核對工具本身完全不變，一樣離線。

## 檔案

- `lark-sync.ps1` — 主程式
- `lark-sync-test.bat` — 雙擊：只連線並列出看得到的檔案，不下載（第一次設定用）
- `lark-sync.bat` — 雙擊：實際下載（每天用這個）
- `lark-sync.config.example.json` — 設定範本

設定檔 `lark-sync.config.json` 內含 App Secret，已列入 `.gitignore`，不會進版控。

## 一次性設定

1. 到 Lark 開放平台建一個**自建應用**，記下 `App ID` 與 `App Secret`。
2. 幫應用開通**雲空間的讀取權限**（查看與下載雲空間檔案）。如果資料夾裡會有 Lark 自己的
   雲文件／表格（不是上傳的檔案），再加上**匯出**權限。
3. 發布應用版本並等管理員通過。
4. **把應用加入那兩個資料夾的協作者**（在 Lark 打開資料夾 → 分享 → 加入你的應用，可讀即可）。
   這步最常被漏掉——少了它，API 會回權限錯誤，或是資料夾看起來是空的。
5. 取得資料夾 token：在 Lark 打開該資料夾，網址是
   `https://xxx.larksuite.com/drive/folder/fldcnAbCdEfGhIjKlMn`，最後那段就是 token。
6. 執行一次 `lark-sync-test.bat`。第一次會自動建立 `lark-sync.config.json` 並要你填。
   填好後再跑一次，確認列出的檔案清單正確。
7. 清單沒問題後，改用 `lark-sync.bat` 實際下載。

## 設定說明

| 欄位 | 說明 |
| --- | --- |
| `domain` | 國際版填 `lark`，中國版飛書填 `feishu` |
| `appId` / `appSecret` | 自建應用的憑證 |
| `ordersFolderToken` | 訂單資料夾 token |
| `shipsFolderToken` | 出貨資料夾 token |
| `outputRoot` | 下載到哪，例如 `C:\出貨核對` |
| `onlyModifiedWithinDays` | 只抓最近幾天內修改的檔案；填 `0` 表示整個資料夾都抓 |
| `includeSubfolders` | 是否連子資料夾一起抓 |
| `exportLarkDocs` | Lark 雲文件／表格要不要匯出成 docx／xlsx |

## 每天怎麼用

1. 雙擊 `lark-sync.bat`。
2. 檔案會下載到 `outputRoot\日期\orders` 與 `outputRoot\日期\ships`，跑完自動開啟資料夾。
3. 把這兩個資料夾分別拖進 `order-check.html` 的左右兩區，按「開始核對」。

依日期分資料夾，所以每天的原始檔都留著，之後要追也查得到。

## 已知行為

- 同名檔案不會互相覆蓋，第二個會變成 `檔名(2).pdf`。
- 檔名裡的 `\ / : * ? " < > |` 會換成底線。
- 清單裡若沒有副檔名，會從下載回應的標頭補回來（核對工具靠副檔名判斷格式）。
- 捷徑會自動解析到原始檔案。
- 單一檔案沒有權限時只會標成失敗並繼續，不會中斷整批。
