# Lance 出貨導航

單一 HTML 檔（`index.html`），無外部依賴，用瀏覽器直接開或以 claude.ai Artifact 發佈即可使用。

線上版本：https://claude.ai/code/artifact/12b5c591-be75-4d9e-9479-e7c6fa8be8ee

## 目的

依 Lance 整理的 momo 出貨流程，一步一步帶著做，每一步都是可打勾的清單，
並在需要複製文字的地方直接產生文字（檔名、NS 訂單名稱、愛上會員編號、給希塔倉的回報訊息）。

## 設計原則（依 Lance 的回饋）

- 不逐項打勾：每一步是固定順序的編號流程，做完按「這一步做好了」即可。
- 看訂單與印單都固定順序：超商 → 第三方常溫 → 第三方冷凍。
- 「今日訂單」是選用功能，不加也能照流程做。
- 每一步完成、每天收工時給一句具體肯定，並顯示累計完成天數與連續工作日。

## 七個步驟

1. 登入 momo SCM 看今天的單（記下未出貨數字、把每張單加到「今日訂單」）
2. 填 Lark 新零售銷售報表（逐欄清單）
3. SCM 下載文件、命名、iLovePDF 解鎖、確認內容（超商／宅配分開）
4. NetSuite 建立銷售訂單，回填 SO 號（每張單逐張打勾）
5. 倉庫出貨：愛上倉走愛上後台；希塔倉在 Lark 回報湯先生（每張單逐張打勾）
6. NetSuite 交貨（不要按送出），Lark 表勾 NS打單與交貨
7. 開「訂單出貨核對」核對今天的出貨，然後收工

## 與「訂單出貨核對」的聯動

第 7 步的按鈕會以 `?date=YYYY-MM-DD&channel=MOMO`（同時放一份在 `#hash`）開啟
「訂單出貨核對」，該頁啟動時會讀取這兩個參數，自動填入出貨日期與通路，並捲到上傳區。
對應程式在 `order-check/index.html` 結尾的 `handoff()`。

## 資料

打勾進度、今日訂單、截單提醒、備註都存在瀏覽器 `localStorage`（以日期分開），跨日自動從第 1 步開始。
設定面板可匯出／還原 JSON 備份。

## 流程內容的來源與待確認事項

流程文字整理自 Lance 的出貨流程筆記。以下幾點筆記中沒有定論，App 內列在「還在等主管回答的問題」，
主管可直接在該處填答案：

- 怎麼判斷哪些訂單是 MOMO 寄倉
- 希塔倉週四不出貨時，其他倉的單是否照常
- SCM「日對帳」每天要做什麼
- 「上傳雲端到希塔資料夾」是愛上倉還是希塔倉的單要做
- 第 7 步核對的兩個資料夾各放什麼（主管定好後填在 App 設定，第 7 步會照著顯示）
